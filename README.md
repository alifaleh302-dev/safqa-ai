# نظام التفاوض الذكي على تليجرام (Telegram AI Negotiator)

نظام **userbot** يتفاوض مع العملاء داخل مجموعات تليجرام بأسلوب بشري، مدعوم بـ **Google Gemini**،
مع **واجهة ويب مستقلة** للإدارة والإعداد. الهدف والمنتجات والأسعار والحدود كلها تُحدَّد من داخل البرومبت.

> ⚠️ **تنبيه:** تليجرام يمنع الاستخدام الآلي للحسابات. استخدم **حساباً مخصّصاً** (لا حسابك الشخصي)،
> وابقِ الحدود منخفضة، ولا ترسل رسائل جماعية. المخاطرة بالحظر مسؤوليتك.

---

## المعمارية

- **Telegram Layer:** Telethon (MTProto) — حساب مستخدم حقيقي، **بدون صلاحيات أدمن**.
- **AI Engine:** Gemini عبر طبقة قرار تُعيد JSON (`reply` / `ignore` / `escalate`).
- **Backend:** FastAPI + SQLAlchemy (SQLite للتطوير، Postgres للإنتاج).
- **Frontend:** React + TypeScript + Vite (واجهة عربية RTL).

راجع `docs/ARCHITECTURE.md` للتفاصيل الكاملة.

```
frontend/  → واجهة الويب (React)
backend/   → API + userbot + محرّك الذكاء
docs/      → التوثيق والتخطيط
```

## التشغيل السريع (تطوير)

### 1) الإعدادات
```bash
cp .env.example .env
# عدّل .env: املأ TELEGRAM_API_ID/HASH و GEMINI_API_KEY و SECRET_KEY
```

### 2) الـ Backend
```bash
cd backend
pip install -r requirements.txt
export PATH="$HOME/.local/bin:$PATH"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 3) الـ Frontend
```bash
cd frontend
npm install
npm run dev     # يعمل على المنفذ 12000 ويمرّر /api إلى الـ backend
```

افتح الواجهة على `http://localhost:12000` ثم سجّل الدخول باسم وكلمة مرور المشرف
(`ADMIN_USERNAME` / `ADMIN_PASSWORD` في `.env`).

## خطوات الاستخدام

1. **الإعدادات:** أدخل Telegram API ID/Hash ومفتاح Gemini ومفتاح التشفير.
2. **تسجيل الدخول:** استخدم بيانات المشرف للدخول إلى الواجهة (JWT).
3. **البرومبتات:** اكتب الهدف والمنتجات والأسعار والحدود والأسلوب (قوالب جاهزة موجودة).
4. **قاعدة المعرفة:** عدّل كتالوج المنتجات (الأسعار والحد الأدنى المخفي والكلمات المفتاحية)
   من صفحة **المعرفة** أو مباشرة من `backend/data/products.json`.
5. **الحسابات:** أضف حساب userbot وسجّل الدخول (رقم ← كود ← كلمة مرور 2FA إن وُجدت).
6. **المجموعات:** أضف معرّف المجموعة، اربطها بالحساب والبرومبت، واختر الوضع:
   - `mention` (موصى به): يرد فقط عند ذكره أو الرد عليه.
   - `always`: يرد على كل رسالة (خطر أعلى).
   - `off`: معطّل.
7. **تجربة الردود:** اختبر ردود الذكاء على رسائل وهمية **دون إرسالها** إلى تليجرام.
8. **المراقبة الحيّة:** شاهد المحادثات والقرارات لحظة بلحظة عبر WebSocket.

## النشر بـ Docker

```bash
cp .env.example .env   # عدّل القيم (Telegram + Gemini + كلمات مرور Postgres)
docker compose up --build
```

ثلاث حاويات: **Postgres** (بحجم دائم) + **backend** (ينتظر صحة القاعدة) + **frontend** (nginx).

- الواجهة: `http://localhost:12000`
- الـ API: `http://localhost:8000`
- تُبنى `DATABASE_URL` تلقائياً من متغيّرات `POSTGRES_*`.
- جلسات Telethon و`products.json` محفوظة في مجلّد `backend/data/` (volume).

## النشر على منصة سحابية (Railway / Render / Fly)

المشروع جاهز للاستضافة. الفكرة: **قاعدة البيانات تُستضاف منفصلة**، والتطبيق يتصل بها عبر `DATABASE_URL`.

### قاعدة بيانات Postgres مُدارة
أنشئ خدمة Postgres على المنصة وانسخ رابط الاتصال الداخلي، مثال Railway:
```
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME
```
> لا تحتاج إضافة `+psycopg2` — الكود يطبّعه تلقائياً.

### حاويات التطبيق
- **backend:** FastAPI (يُنشئ الجداول تلقائياً عند الإقلاع — لا حاجة لتشغيل migrations يدوياً).
- **frontend:** nginx يخدم الواجهة ويوجّه `/api` و`/ws` إلى الـ backend.
- عند استخدام قاعدة بيانات خارجية، يمكن حذف خدمة `db` من `docker-compose.yml` وضبط `DATABASE_URL` في `.env`.

### متغيّرات البيئة المطلوبة
| المتغيّر | الوصف |
|---|---|
| `DATABASE_URL` | رابط Postgres المُدار |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | من my.telegram.org |
| `GEMINI_API_KEY` | مفتاح Google AI Studio |
| `SECRET_KEY` | تشفير جلسات Telethon |
| `JWT_SECRET` | توقيع رموز الدخول |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | دخول الواجهة |

> ⚠️ في بيئة سحابية بلا تخزين دائم، احفظ مجلّد `backend/data/` على volume، وإلا فُقدت جلسات تليجرام عند كل إعادة نشر.

## الأمان

- **مصادقة JWT** على الواجهة وكل مسارات API (عدا `/api/health` و`/api/auth/login`).
- **بثّ WebSocket** موثَّق عبر رمز الاستعلام؛ الاتصال غير الموثّق يُرفض.
- تُشفَّر جلسات Telethon في قاعدة البيانات بمفتاح `SECRET_KEY` (Fernet).
- سجلّ قرارات كامل (`decisions`) + أحداث (`events`) للتدقيق.
- حالات التصعيد (`escalate`) تُخرج أي أمر حساس من يد الذكاء إلى الإنسان.
- **غيّر `ADMIN_PASSWORD` وكلمات مرور Postgres قبل الإنتاج، ولا ترفع `.env` أو `*.session` إلى git.**
