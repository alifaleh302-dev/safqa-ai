# نظام التفاوض الذكي على تليجرام — خطة البنية المعمارية

> **الهدف:** نظام يقوم بعمل تفاوض مع العملاء داخل مجموعات تليجرام بأسلوب بشري مقنع،
> عبر userbot مرتبط بمحرّك ذكاء اصطناعي، مع واجهة ويب للإدارة والإعداد.

---

## 1. نظرة عامة على المكوّنات (High-Level Architecture)

النظام يتكوّن من **5 مكوّنات رئيسية** تعمل معاً:

```
┌──────────────────────────────────────────────────────────────────┐
│                        واجهة الويب (Admin UI)                     │
│      Next.js + TypeScript  →  إدارة الحسابات/المجموعات/البرومبت    │
└───────────────────────────────┬──────────────────────────────────┘
                                │ REST + WebSocket
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                   الـ API Gateway (Backend API)                   │
│     FastAPI (Python) → Auth, CRUD, Live Monitor, Metrics          │
└───────┬───────────────────┬───────────────────┬──────────────────┘
        │                   │                   │
        ▼                   ▼                   ▼
┌──────────────┐   ┌──────────────────┐   ┌────────────────────┐
│  Postgres    │   │  Redis + Celery  │   │   AI Engine        │
│  (البيانات)   │   │ (طوابير + تخزين) │   │  (LLM + Prompting) │
└──────────────┘   └────────┬─────────┘   └─────────┬──────────┘
                            │                        │
                            ▼                        │
                 ┌───────────────────────────────────▼──────────┐
                 │              Telegram Layer                   │
                 │   Telethon Userbot(s) + Session Manager       │
                 │   (يقرأ الرسائل ويرد على المجموعات)             │
                 └───────────────────────────────────────────────┘
```

## 2. شرح كل مكوّن

### 2.1 طبقة تليجرام (Telegram Layer) — أهم جزء حساس

- **التقنية:** `Telethon` (مكتبة Python تعمل عبر MTProto، تتيح التحكم بحساب مستخدم حقيقي وليس بوت رسمي).
- **السبب:** البوتات الرسمية (Bot API) **لا تستطيع** قراءة رسائل المجموعات إلا إذا كانت أدمن ومُفعّلة، ولا تمتلك حضوراً بشرياً. الـ userbot يعمل كحساب مستخدم عادي.
- **المكوّنات الفرعية:**
  - `Session Manager`: يخزّن جلسات (sessions) كل حساب مشفّرة، ويدير تسجيل الدخول (رقم + كود + 2FA).
  - `Group Listener`: يستمع للرسائل الجديدة في المجموعات المُراقَبة فقط (whitelist).
  - `Context Builder`: يجمع آخر N رسالة من المحادثة لبناء سياق يفهمه الـ LLM.
  - `Message Sender`: يرسل الردود مع محاكاة السلوك البشري (انظر 2.5).

> ⚠️ **تحذير مخاطر:** تليجرام يمنع الـ userbots في بعض الحالات وقد يحظر الحساب. يجب تصميم النظام ليعمل على **حسابات مخصّصة** (لا الحساب الشخصي)، مع حدود معدّل صارمة، وعدم إرسال رسائل جماعية (spam).

### 2.2 محرّك الذكاء الاصطناعي (AI Engine)

- **التقنية:** مزوّد LLM (OpenAI / Anthropic / نموذج محلي) عبر طبقة تجريد واحدة.
- **المكوّنات الفرعية:**
  - `Prompt Manager`: يدير نسخ البرومبت (system prompt) لكل حملة/مجموعة/شخصية، مع إصدارات (versioning) وإمكانية A/B testing.
  - `Persona Engine`: يعطي الـ userbot شخصية (اسم، لهجة، أسلوب، معلومات خلفية).
  - `Negotiation Policy`: يحدّد الأهداف والحدود (السعر الأدنى، ما يُسمح بوعده، متى يصعّد للإنسان).
  - `Guardrails`: فلاتر تمنع الردود المخالفة أو الخارجة عن السياسة (مثل وعد بما لا يمكن الوفاء به).
  - `RAG (اختياري)`: قاعدة معرفة (كتالوج المنتجات/الأسعار/الأسئلة الشائعة) تُغذّي الـ LLM.

### 2.3 الـ Backend / API Gateway

- **التقنية:** `FastAPI` (Python) — سريع، غير متزامن، ويدعم WebSocket للـ live monitoring.
- **المسؤوليات:**
  - المصادقة والصلاحيات (JWT + RBAC).
  - CRUD للحسابات، المجموعات، البرومبتات، الحملات.
  - بثّ الرسائل الحيّة للواجهة (WebSocket).
  - إحصاءات (عدد الردود، نسبة التحويل، تكلفة التوكنز).

### 2.4 قاعدة البيانات والطوابير

- **PostgreSQL:** تخزين دائم (الحسابات، المجموعات، المحادثات، الرسائل، البرومبتات، الحملات، الأحداث).
- **Redis:** كاش + Rate limiting counters + pub/sub للـ WebSocket.
- **Celery (أو ARQ):** مهام خلفية:
  - توليد الرد عبر الـ LLM (خارج حلقة الاستماع لعدم حجبها).
  - إرسال الرسائل مع التأخير البشري.
  - مهام مجدولة (تقارير، تنظيف، متابعة).

### 2.5 محاكاة الأسلوب البشري (Human-likeness) — سرّ الإقناع

هذا ما يميّز النظام. يجب تطبيق:
- **تأخير القراءة والكتابة:** تأخير قبل الرد متناسب مع طول الرسالة + عشوائية.
- **مؤشر "يكتب الآن":** إرسال `typing action` قبل الرد.
- **تقسيم الرسائل:** إرسال الرد على أجزاء قصيرة متتابعة كما يفعل البشر.
- **أخطاء بشرية مقصودة:** أحياناً رسالة تصحيحية ("*" أو إعادة صياغة).
- **أوقات النشاط:** عدم الرد في ساعات النوم (جدول زمني لكل حساب).
- **تنويع الصياغة:** منع تكرار نفس الردود الحرفية (تجنّب كشف النمط).
- **حدود معدّل:** عدد ردود/ساعة منخفض لكل حساب.

### 2.6 واجهة الويب (Admin UI)

- **التقنية:** `Next.js` + TypeScript + Tailwind (متوافقة مع إمكانية بناء Canvas App لاحقاً).
- **الصفحات الأساسية:**
  1. **لوحة التحكم (Dashboard):** إحصاءات حيّة.
  2. **الحسابات:** إضافة/تسجيل دخول userbot، حالة الاتصال.
  3. **المجموعات:** قائمة مراقَبة، ربطها بحملة/شخصية/برومبت.
  4. **محرّر البرومبت:** كتابة system prompt + معاينة (playground) + إصدارات.
  5. **الحملات:** هدف + حدود + جدول + قواعد تصعيد.
  6. **المراقبة الحيّة:** مشاهدة المحادثات لحظة بلحظة + إمكانية تدخّل يدوي.
  7. **الإعدادات:** مفاتيح الـ LLM، حدود المعدّل، إعدادات الأمان.

## 3. نموذج البيانات (مبدئي)

```
accounts        (id, phone, session_enc, status, persona_id, created_at)
personas        (id, name, tone, background, language, style_notes)
prompts         (id, name, version, system_text, variables, created_at)
campaigns       (id, name, goal, min_price, rules, schedule, status)
groups          (id, telegram_id, title, campaign_id, mode, active)
conversations   (id, account_id, group_id, telegram_thread_id, state)
messages        (id, conversation_id, direction, text, tokens, created_at)
decisions       (id, message_id, action, confidence, reason, escalated)
audit_logs      (id, actor, action, payload, created_at)
```

## 4. تدفّق العمل الأساسي (Message Flow)

```
رسالة جديدة في مجموعة مُراقَبة
        │
        ▼
[Group Listener] → هل المجموعة مُفعّلة؟ ──لا──► تجاهل
        │ نعم
        ▼
[Context Builder] → يجمع آخر N رسالة + بيانات العميل
        │
        ▼
[Policy Check] → هل يجب أن نرد؟ (منشور؟ ذُكرنا؟ سؤال؟) ──لا──► تجاهل
        │ نعم
        ▼
[Prompt Manager] → يبني البرومبت الكامل (شخصية + سياسة + سياق + RAG)
        │
        ▼
[AI Engine] → يولّد الرد + درجة ثقة + قرار (رد / تصعيد)
        │
        ▼
[Guardrails] → فحص الرد ──مخالف──► تصعيد لإنسان
        │ سليم
        ▼
[Human-like Sender] → typing + تأخير + تقسيم → إرسال
        │
        ▼
[Logger] → تخزين + تحديث الإحصاءات + بثّ للواجهة
```

## 5. الأمان والامتثال

- تشفير الجلسات (sessions) بمفتاح رئيسي (KMS / Fernet).
- عزل الحسابات: كل حساب له حدود ومعدّلات مستقلة.
- سجلّ تدقيق كامل (audit log) لكل قرار ورد.
- Kill switch: إيقاف فوري لكل الحسابات من الواجهة.
- سياسة تصعيد واضحة: الحالات الحساسة تذهب لإنسان.
- الالتزام بشروط استخدام تليجرام وتجنّب الـ spam.

| الطبقة        | التقنية                          |

## 7. مراحل التنفيذ (Roadmap)

### المرحلة 0 — التحقق (Proof of Concept)
- userbot واحد + مجموعة واحدة + برومبت ثابت + رد آلي.
- الهدف: إثبات أن الرد مقنع وأن الاتصال يعمل.

### المرحلة 1 — الأساس (MVP)
- Backend + DB + userbot واحد.
- واجهة ويب بسيطة: إضافة حساب، إضافة مجموعة، كتابة برومبت.
- تسجيل كل الرسائل.

### المرحلة 2 — الذكاء والتفاوض
- محرّك البرومبتات + الشخصيات + سياسة التفاوض.
- Guardrails + تصعيد.
- محاكاة الأسلوب البشري الكاملة.

### المرحلة 3 — التوسّع والإدارة
- تعدد الحسابات والمجموعات.
- مراقبة حيّة + تدخّل يدوي.
- إحصاءات + A/B testing للبرومبتات.

### المرحلة 4 — التصلّب للإنتاج
- حدود معدّل متقدمة + مقاومة الحظر.
- أمان + سجل تدقيق + نسخ احتياطي.
- نشر على سيرفرات + مراقبة (observability).
